## 2026-11-10 — VSCode-style line selection (`Shift+↑`/`Shift+↓`)
- Added `Action::SelectUp` / `Action::SelectDown` to `nnano-core::editor`. Either one starts a mark at the cursor when none exists and then moves one line through the same `move_vertical` path, so `follow()` drags the head and the goal column is kept — the selection grows by whole rows without `M-A`, exactly like an editor's shift+arrow.
- `term/input.rs`: two new rows, `Shift+Up` / `Shift+Down`, placed **before** the plain arrows because a row matches when its modifiers are a subset of the event's (`Shift+Up` would otherwise decode as `MoveUp`). The help and the palette pick them up from the table, with ten translation rows in `i18n/keys.rs`.
- Panels have no mark, so `App::apply` maps the two actions to `MoveUp`/`MoveDown` while an overlay owns the keys: the settings/palette/help highlight still moves on `Shift+↑`/`↓` instead of silently doing nothing.
- Kept nano's mark semantics on purpose: once a mark exists, any movement extends it; `Shift` only *starts* the mark. `Esc` still clears it.
- Docs: the navigation table and a note in `docs/<lang>/shortcuts.md` for all ten languages; `AGENTS.md` status, keymap and implemented-rows lines updated.
