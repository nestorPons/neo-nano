# 2026-11-10 — `Shift+↑`/`Shift+↓` line selection

Petición: seleccionar varias filas al estilo VS Code con `Shift+↑` y `Shift+↓`.
El historial de decisiones sigue en `LOG.md`.

## Comportamiento

| Tecla | Antes | Ahora |
|---|---|---|
| `Shift+↑` | `MoveUp` (la fila de `Up` aceptaba `Shift` por la regla de subconjunto) | `SelectUp`: crea la marca en el cursor si no hay ninguna y sube una línea |
| `Shift+↓` | `MoveDown` | `SelectDown`: crea la marca en el cursor si no hay ninguna y baja una línea |
| `↑` / `↓` | mueve una línea | igual; con una marca activa la extiende, como en nano |
| `Shift+↑`/`↓` dentro de un panel | mueve la fila resaltada | igual (se traduce a `MoveUp`/`MoveDown` en `App::apply`) |

- La columna visual se conserva entre líneas de distinta longitud.
- `Esc` sigue limpiando la marca; `M-Z` sigue activando la marca rectangular.
- No se cambia la semántica de nano: `Shift` **inicia** la marca, y con una marca
  activa cualquier movimiento la extiende.

## Barra de desplazamiento y total de líneas

Petición: una barra de scroll a la derecha y, en la barra de estado, el total de
líneas del documento junto a la posición (`1:5/100`).

### Comportamiento

- `ui::areas` ahora devuelve `(pestañas, texto, barra, estado)`: reserva la última
  columna del área de texto para una barra de una celda. La columna se reserva
  siempre (con ancho ≥ 2), así el texto no se reajusta cuando el archivo crece
  por encima de la pantalla.
- La barra dibuja un pulgar proporcional (`█`) y una pista atenuada (`│`); con un
  archivo que cabe entero no dibuja nada y la columna queda limpia.
- Clic en la barra: la celda pulsada pasa a ser la parte superior de la vista,
  acotada a la última página. Va por `Action::ScrollView`, así que el cursor no se
  mueve y se mantiene el camino único de mutación.
- La barra de estado muestra `línea:columna/total` (`display_position` +
  `line_count`). En un búfer vacío: `1:1/1`.
- `^H` añade la fila *Click bar / Jump to that page* (10 idiomas) y el panel de
  ayuda crece solo porque su alto se calcula desde `content_len()`.

### Archivos modificados

## Gramáticas de sintaxis para extensiones populares

Petición: soporte para las extensiones más populares (html, js, php, htmx, phtml,
jx, go, etc.).

### Diagnóstico

En un pty, con los grammars de `/usr/share/nano` cargados, ya se resaltaban
`.html`, `.js`, `.php`, `.phtml` y `.go`; **no** se resaltaban `.htmx`, `.jx` ni
`.ts`. Además el paquete `nnano` no depende de `nano`, así que una máquina sin
nano no tenía ningún grammar.

### Cambios

- Nuevo asset `crates/nnano-core/assets/syntax/popular.nanorc` (formato nanorc,
  reglas propias, sin copiar las GPL de nano) embebido con `include_str!`.
- `SyntaxSet::load` lo añade **al final**: usuario → `/usr/share/nnano/syntax` →
  `/usr/share/nano` → embebidas. `select` devuelve el primer match, así que un
  grammar de usuario o distro con el mismo nombre gana y las embebidas rellenan
  huecos (sobre todo si no hay nano instalado).
- Patrones ampliados: html/htmx/vue/svelte/astro, js/ts/tsx/jsx/jx, php/phtml,
  go, css/scss/sass/less, json, xml/svg, yaml/yml, toml, ini, dotenv, Dockerfile,
  ignore, markdown/mdx, sh, python, rust, c/c++, java, sql. `htmx` tiene grammar
  propia para pintar `hx-*` en bright cyan.
- Registro del formato de gramáticas en `AGENTS.md`, README, man page y changelog.
- Tests nuevos: el asset compila entero (se comparan las líneas `syntax`/`color`
  con lo que el parser devuelve), cada extensión popular selecciona el grammar
  esperado, `load` sin directorios sigue cargando las embebidas y un grammar
  cargado antes gana.

### Verificación

- `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo test --workspace` → **380 tests** (191 core, 177 TUI, 8 CLI, 4 docs).
- `groff -man -z man/nnano.1` — limpio.
- Pty real con `target/release/nnano`: `.htmx` incluye `38;5;14` (hx-*), `.jx` y
  `.ts` colorean con las reglas de JS, `.toml`, `.env`, `Dockerfile`, `.gitignore`
  y `.scss` muestran color; `.html`, `.php`, `.phtml` y `.go` siguen bien.

## Sitio web (GitHub Pages)

Petición inicial: una página gratuita, básica, con diseño terminal retro que
explique qué es neo-nano, con imagen, documentación, atajos y autor. Segunda
petición: pasarla al inglés y darle soporte para el resto de idiomas de la app
con la API de idiomas de Google, como en nestorpons.com.

### Entrega

- `docs/index.html` (inglés, fuente): hero tipo terminal (logo ASCII, cursor
  parpadeante, `$ nnano README.md`), qué es, captura, 8 tarjetas de
  características, instalar (AUR y fuente, con botón de copiar), tabla de atajos
  esenciales, proyecto y autor (Nestor Pons), pie.
- `docs/shortcuts.html` (inglés): referencia completa (file, editing,
  navigation, search, interface, cambios respecto a nano, límites del terminal,
  prompts/recuperación) y enlaces a los diez idiomas. `docs/atajos.html` es una
  redirección para no romper el enlace anterior.
- `docs/style.css` + `docs/site.js`: sin dependencias ni fuentes externas.
  Paleta fósforo/ámbar, scanlines sutiles, tarjetas con borde completo y radio
  6 px, `prefers-reduced-motion`, `:focus-visible`, skip link, propiedades
  lógicas para RTL.
- `docs/translator.js`: Translator API del navegador (`window.Translator`), la
  misma que usa nestorpons.com — en el dispositivo, sin clave, sin servidor y
  sin coste. Inglés como `sourceLanguage`; selector con los diez idiomas de la
  app (`en, es, zh, hi, ar, fr, bn, pt, id, ja`), `availability()` para ocultar
  los no soportados, descarga del modelo con progreso, traducción por bloques
  `[data-i18n]` y atributos `[data-i18n-attr]`, `<code>`/`<kbd>` preservados,
  RTL para árabe y preferencia en `localStorage`. Sin `Translator`, el selector
  queda oculto y el sitio sigue en inglés.
- `docs/assets/neo-nano.png` (1365×714, copiada de `~/Descargas`),
  `docs/assets/favicon.svg`, `docs/.nojekyll`.
- Publicación: rama `main`, carpeta `/docs`, sin GitHub Actions ni build.
- `homepage` del repo y de `Cargo.toml` apuntan a la página.

### Verificación

- `python3 -m http.server` + Chromium headless: capturas de escritorio (1280 px),
  móvil (390 px), `shortcuts.html` y una simulación con `window.Translator`
