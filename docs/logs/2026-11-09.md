## AUR publishing runbook

- Question from the user: how to upload to `yay`. Corrected the model: `yay` is a
  client, the package is published by pushing a git repo to `aur.archlinux.org`;
  no upload step and no review queue, `yay -S nnano` works as soon as the push
  lands.
- Checked: `nnano` and `nnano-git` are **free** on the AUR (`rpc/v5/info` returns
  nothing for both), and `ssh aur@aur.archlinux.org` answers
  `Permission denied (publickey)` — the account key is the only missing piece.
- Rewrote `packaging/README.md`: `v0.1.0` → `v0.1.1`, the man page and the three
  completions added to the installed-file table, the one-time AUR setup (account,
  SSH key at `/account/`, the check command), the first-push flow including the
  harmless `cloned an empty repository` warning, the per-release loop, the RPC
  verification and `extra-x86_64-build`.
- Recorded two maintainer traps: the AUR does **not** regenerate `.SRCINFO` (the
  web page and every helper read it, so it must be committed with the PKGBUILD),
  and `makepkg --printsrcinfo` does not run `pkgver()`, so `nnano-git` needs its
  `pkgver` refreshed by hand before each push.
- Verified both `.SRCINFO` files are byte-identical to `makepkg --printsrcinfo`
  output. `namcap` is not installed here, so the lint step stays documented but
  unrun.
