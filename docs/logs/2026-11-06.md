## Help overlay (`^H`)

- `^H` (and `F1`) opens a floating, scrollable reference of every implemented binding; the status bar shows `^H: help`.
- Backspace is the terminal's Backspace key (`0x7F`). On a terminal that sends `0x08` for Backspace, that key opens help instead of deleting — documented trade-off.

## Known gaps

`^R` reload from disk and `M-I` insert-file at cursor (both documented in the shortcut references). No LSP, no plugins, no packaging.

## File prompts, recovery file, OSC 52 (`2026-11-06`)

- `M-S` and `^S` on a buffer with no name open one-line prompts (*Save as*, *Open*, *Go to line*, *Execute*), drawn on the status row; `Tab` completes a path in the two file prompts.
- `^O` opens a path in a new buffer, `^G` accepts `line[,column]` or `+N`/`-N`, `^J` re-wraps to the text width, `M-X` inserts a command's stdout, `Ctrl+←/→` move by word.

## Help and palette read the keymap (`^H`, `^P`)

- `term/input.rs` holds one `KEYMAP` table (`chord` + `action` + `group` + `label`); `decode` is a lookup over it, not a separate `match`.
- `^H` help is generated from that table, so it lists every working binding (50 rows: Files, Editing, Move, Search, Interface) plus hand-written prompt answers and mouse notes.
- `^P` palette prints each command's chord on the right edge and also filters by it (`ctrl+q` → Quit).
- Tests: every row decodes to its own action, no duplicate chord, every binding has a section, every command advertises a live chord.

## Syntax fix: multiple matches per rule (`syntax.rs`)

- `highlight` advanced the byte cursor but not the char cursor after a match, so a rule's second and later hits on the same line landed on earlier text (keywords, links, `*emphasis*`).
- Fixed by setting `scanned_char = end`; regression test `a_rule_can_match_several_times_on_one_line`. Found while checking `.md` highlighting.
